# 扣子工作流：抖音热搜写入飞书多维表格

- **收录日期**：2026-08-13
- **标签**：#工具与通用 #扣子 #工作流 #抖音热搜 #飞书多维表格 #自动化 #自媒体

> [!note] 时效提醒
> 扣子插件名称、节点参数和飞书授权界面可能更新。搭建时以当前界面的真实输出字段为准，尤其不要直接照抄示例变量名。

## 核心内容

这套工作流解决的是：**自动抓取抖音热搜，用大模型补充摘要和分类，再批量写进飞书多维表格。**

```text
开始
  ↓
抖音热搜插件：获取原始数据
  ↓
大模型：保留标题，生成摘要和分类
  ↓
代码节点：转换成飞书 records 数组
  ↓
飞书 add_records：批量新增记录
  ↓
结束：返回写入数量
```

它适合作为自媒体选题池的“采集入口”。飞书负责沉淀和筛选热点，后续可以再接选题评分、脚本生成、剪辑和发布流程。

## 一、飞书表格字段

第一次调试时，字段类型尽量简单，先确保能写入，再优化为链接或日期类型。

| 字段 | 初次建议类型 | 数据来源 |
|---|---|---|
| 标题 | 文本 | 抖音插件原始标题 |
| 摘要 | 多行文本 | 大模型生成 |
| 分类 | 文本 | 大模型判断 |
| 热度 | 数字 | 抖音插件 |
| 排名 | 数字 | 抖音插件或列表顺序 |
| 链接 | 文本 | 抖音插件原始链接 |
| 抓取时间 | 文本 | 模型返回或代码生成 |

## 二、最容易填错的两个 ID

飞书多维表格地址一般类似：

```text
https://xxx.feishu.cn/base/APP_TOKEN?table=TABLE_ID&view=VIEW_ID
```

| 参数 | 识别方法 | 不要填成 |
|---|---|---|
| `app_token` | `/base/` 后、`?` 前的部分 | 完整 URL |
| `table_id` | `table=` 后的 `tbl...` | `view_id`、表名、`table=tbl...` |
| `view_id` | 通常是 `vew...` | 不需要传给 `add_records` |

> [!warning] 密钥与权限
> 不要把真实 `app_token`、授权信息或账号凭据写进公开文档、代码仓库和聊天记录。若已经泄露，应及时检查授权范围、表格权限，并按需要撤销或更换授权。

## 三、扣子节点配置

### 1. 开始节点

插件支持数量参数时，可增加：

| 参数名 | 类型 | 默认值 |
|---|---|---|
| `top_n` | Integer | 20 |

### 2. 抖音热搜插件

先单独运行插件，查看它真实返回了哪些字段。至少要有标题；理想结构是：

```json
[
  {
    "rank": 1,
    "title": "热搜标题",
    "hot_value": 1234567,
    "url": "https://www.douyin.com/"
  }
]
```

不同插件可能把字段写成 `hot`、`link`、`share_url` 或 `detail_url`，代码映射要跟着真实输出调整。

### 3. 大模型节点

- 温度可先设为 `0.2`，减少格式漂移。
- 保留原始标题、排名、热度和链接。
- 只让模型补摘要与分类。
- 原始数据没有链接时返回空字符串，不能让模型编造链接。
- 强制只输出合法 JSON 数组，不带 Markdown 代码块和解释文字。

建议统一为下面的字段：

```json
[
  {
    "rank": 1,
    "title": "热搜标题",
    "summary": "一句话摘要",
    "category": "科技",
    "hot_value": 123456,
    "url": "原始链接",
    "capture_time": "2026-08-13 12:00:00"
  }
]
```

### 4. 代码节点

输入是大模型返回的 `llm_json`，输出为：

| 输出变量 | 类型 | 用途 |
|---|---|---|
| `records` | Array | 传给飞书 `add_records` |
| `count` | Integer | 统计有效记录数 |

飞书批量新增要求的关键结构是：

```json
[
  {
    "fields": {
      "标题": "热搜标题",
      "摘要": "热搜摘要",
      "分类": "科技",
      "热度": 100000,
      "排名": 1,
      "链接": "https://www.douyin.com/",
      "抓取时间": "2026-08-13 12:00:00"
    }
  }
]
```

代码节点的任务不是重新创作内容，而是做三件事：

1. 把字符串 JSON、对象或数组统一转换成列表。
2. 兼容不同字段名，并把排名、热度转换成整数。
3. 包装成飞书需要的 `[{"fields": {...}}]` 格式。

### 5. 飞书节点

选择飞书多维表格的 `add_records` 或“批量新增记录”，绑定：

| 参数 | 绑定内容 |
|---|---|
| `app_token` | 目标多维表格的 token |
| `table_id` | 目标数据表的 `tbl...` ID |
| `records` | 代码节点的 `records` |

结束节点可返回：

```text
抖音热搜采集完成，共写入 {{代码.count}} 条记录。
```

## 四、正确测试顺序

| 顺序 | 只测什么 | 通过标准 |
|---|---|---|
| 1 | 抖音插件 | 能看到标题，并确认有没有真实链接 |
| 2 | 大模型 | 输出合法 JSON 数组，没有代码块和解释 |
| 3 | 代码节点 | `records` 是数组、`count` 是数字、每项有 `fields` |
| 4 | 飞书节点 | 先只写 1 条，字段类型和权限均正确 |
| 5 | 整体工作流 | 飞书新增条数与 `count` 一致 |

逐节点测试比一次运行整个流程更容易定位问题。测试成功后再把数量恢复到 20 条或 50 条。

## 五、常见问题

| 问题 | 常见原因 | 检查方法 |
|---|---|---|
| `TableIdNotFound` | 把 `view_id`、完整 URL 或表名当成 `table_id` | 确认是同一张表里的 `app_token` 和 `tbl...` |
| 从第 6 行开始新增 | 表中已有 5 条记录 | `add_records` 是追加，不会覆盖 |
| 链接为空 | 原始插件没有返回 URL | 先看插件原始输出，不能让模型编造 |
| `records` 为空 | JSON 解析失败、标题字段没匹配或节点绑错 | 检查代码输入和真实字段名 |
| 权限不足 | 授权账号不对或没有编辑权限 | 核对账号、表格权限和应用访问范围 |
| 链接写入失败 | 飞书字段是“超链接”而代码传了字符串 | 统一飞书字段类型与代码数据结构 |

飞书“超链接”字段需要对象格式：

```python
"链接": {
    "link": str(url),
    "text": "打开抖音"
} if url else ""
```

若字段是普通文本，则保持：

```python
"链接": str(url)
```

## 六、验收标准

- 能获取抖音热搜数据。
- 大模型稳定输出合法 JSON。
- 代码节点生成非空 `records` 数组。
- 飞书 `add_records` 执行成功。
- 飞书新增条数与 `count` 一致。
- 标题、排名、热度、摘要和分类正常写入。
- 原始插件有 URL 时，链接也能正常写入。
- 明确多次运行是追加数据，不是覆盖数据。

## 这条知识对我有什么用

这张卡可以把“找热点”从手动刷抖音变成可重复执行的数据采集流程，适合建立自媒体选题池。对你学习编程也有帮助：它把插件调用、JSON结构、Python数据清洗、字段映射和接口排错串成一个小型自动化项目。

具体建议：先只写入 1 条数据完成全链路测试，再增加到 20 条；成功后在飞书里增加“是否值得做”“适合账号”“选题角度”“处理状态”字段，把热搜库升级成选题管理表。
